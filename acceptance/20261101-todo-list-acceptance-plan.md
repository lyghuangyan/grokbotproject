## 1. 任务拆解与分派

**产品经理**
- P1 澄清需求边界，出一页简版 PRD，写清功能说明和本期不做的内容（登录、后端、同步、编辑、分类、截止日期、拖拽、筛选）
- P2 写 4–5 条用户故事，对应五个功能
- P3 定交互规则：空输入和纯空格不能添加、最大长度（建议 200 字）、新待办插入位置（建议置顶）、删除是否要确认（建议不要）、已完成项是否换位置（建议保持原位）
- P4 给每条用户故事写 Given/When/Then 验收标准

**UI/UX 设计**
- D1 单页布局：标题、输入框加添加按钮、列表区、底部统计（如"剩余 N 项"）
- D2 组件和状态规范：输入框、按钮、待办项的未完成/已完成/悬停态、删除按钮、空状态
- D3 视觉规范：色板、字体字号、间距、圆角，基于 shadcn/ui 或 Ant Design 风格，不做花哨装饰
- D4 桌面端（≥1024px）和移动端（≤480px）两套稿子

**全栈开发**
- E1 工程初始化（建议 Vite + React + TypeScript，纯 HTML/CSS/JS 也可以）和 README
- E2 数据层：结构为 `{ id, text, completed, createdAt }`，封装 localStorage 读写，数据损坏或存储不可用时要能兜底
- E3 实现全部五个功能
- E4 按设计稿还原样式，含响应式
- E5 自测后提 PR，附截图和自测记录

**测试**
- T1 覆盖五个功能的用例
- T2 边界和异常用例：空输入、纯空格、超长文本、HTML 注入、500 条大数据量、localStorage 被禁用或数据损坏
- T3 兼容性：Chrome、Safari、Firefox、Edge 最新版和移动端浏览器
- T4 执行测试，出报告、缺陷单和回归结果
- T5 上线前的验收清单

| D1 上午 | P1–P4 | 参与需求评审 | 评审，E1 初始化 | 评审，开始 T1 |

## 3. 风险点

- **范围蔓延**：编辑、筛选、拖拽这类"顺手加"会拖排期，本期不做的内容已经写明，新需求放下一期。
- **交互细节没定**：开发和测试理解不一致会返工，所以 PM 要在 D1 中午前把规则清单定下来。
- **localStorage 不可用或数据损坏**（隐私模式、存储满）：可能白屏或丢数据，读写要加 try/catch，失败时回退为空列表并提示。
- **XSS**：用户输入一律按纯文本渲染，不用 innerHTML 拼接。
- **设计过度或出稿偏晚**：基于成熟组件库，D1 当天定稿，开发可以先做功能再套样式。
- **数据只在本地**：换浏览器或清缓存就没了，PRD 里要说明，以后需要同步再单独立项。
- **技术栈未定**：D1 上午评审时确认。

## 4. 验收标准概要

- **功能**：列表能正常显示且有空状态；点按钮或按回车都能添加，添加后输入框清空；空输入不能添加；完成/未完成可以切换，已完成项有明显区分；删除只影响当前条目；刷新或重开后数据和状态完整保留；存储异常时不白屏。
- **安全与质量**：输入 `<script>alert(1)</script>` 只显示成文本不执行；控制台无报错；500 条数据时操作不卡。
- **视觉与体验**：和设计稿一致；桌面和移动端无错位、无横向滚动；有悬停和聚焦态，用键盘能完成添加。
- **兼容性**：四大主流浏览器最新版都正常。
- **交付物**：PRD、设计稿、代码 PR 和 README、测试报告和验收清单都已提交，没有未关闭的严重或阻塞级缺陷。
