## 1. 背景与目标

用户需要一个打开即用的轻量待办工具，用来快速记下要做的事、勾掉已完成的事、清掉不需要的事。

本期目标是交付一个单页 Web 应用，覆盖待办的「查看、添加、标记完成/未完成、删除」四个核心动作，数据保存在浏览器本地（localStorage），刷新页面后数据不丢失。

**成功标准**

- 四个核心功能全部可用，且满足第 5 节的交互规则。
- 刷新或关闭后重新打开页面，待办列表与完成状态保持一致。
- 页面风格现代、简洁、专业，无多余装饰。

## 2. 范围

### 2.1 本期要做

1. 显示待办列表（含空状态）
2. 添加新待办
3. 标记完成 / 取消完成
4. 删除待办
5. 数据保存在浏览器 localStorage

### 2.2 本期不做

以下内容明确不在本期范围内，开发与设计不应实现或预留可见入口：

- 登录 / 账号体系
- 后端服务与接口
- 多端或多浏览器数据同步
- 编辑已有待办的内容
- 分类 / 标签
- 截止日期 / 提醒
- 拖拽排序
- 筛选（如「全部 / 未完成 / 已完成」切换）

## 3. 目标用户与使用场景

- **目标用户**：需要临时记录个人事项的普通用户，单人、单设备使用。
- **典型场景**：工作间隙打开页面，输入「回复客户邮件」并回车添加；完成后勾选；不需要的条目直接删除。

## 4. 功能需求

### F1 显示待办列表

- 页面加载时从 localStorage 读取数据并渲染列表。
- 每条待办展示：完成状态勾选框、待办文本、删除按钮。
- 已完成的待办以视觉区分（如文字删除线 + 降低对比度），但仍保留在列表原位置。
- 列表为空时显示空状态提示，例如「还没有待办，添加一条吧」。
- 列表顺序：按创建时间倒序，最新添加的在最上方。

### F2 添加新待办

- 页面顶部提供一个输入框和一个「添加」按钮。
- 用户可点击「添加」按钮或在输入框中按 Enter 提交。
- 提交前对输入内容做首尾空格去除（trim）。
- 校验规则：
  - 内容为空或只含空格时，不添加，不清空输入框，「添加」按钮处于禁用态。
  - 最大长度 200 字符；输入框限制最多输入 200 字符（含粘贴超长内容时截断至 200）。
- 添加成功后：新待办插入列表最上方，默认状态为未完成；输入框清空并保持焦点，方便连续添加。

### F3 标记完成 / 取消完成

- 点击勾选框（或点击待办文本区域）切换完成状态。
- 切换后待办位置不变，不自动移到底部或顶部。
- 状态变化立即写入 localStorage。

### F4 删除待办

- 每条待办提供删除按钮（建议使用图标按钮，悬停或聚焦时可见即可，移动端常显）。
- 点击后直接删除，不弹出确认框。
- 删除后立即写入 localStorage；若删除后列表为空，显示空状态。

### F5 本地数据存储

- 使用浏览器 localStorage 保存全部待办数据。
- 任何新增、状态切换、删除操作后立即同步写入。
- 页面刷新、关闭后重新打开，数据保持一致。

## 5. 交互规则汇总

| 规则 | 说明 |
| --- | --- |
| 空输入不能添加 | 输入为空字符串时，「添加」按钮禁用，按 Enter 无效果 |
| 纯空格不能添加 | trim 后为空视同空输入 |
| 首尾空格处理 | 保存时去除首尾空格，中间空格保留 |
| 最大长度 | 200 字符，超出部分无法输入 |
| 新待办位置 | 插入列表最上方 |
| 删除确认 | 不需要确认，点击即删除 |
| 已完成项位置 | 保持原位，不重新排序 |
| 添加后输入框 | 清空并保持焦点 |

## 6. 数据说明

### 6.1 数据只保存在本地

本期数据仅保存在当前浏览器的 localStorage 中，没有任何后端或云端存储。这意味着：

- 数据只在当前设备、当前浏览器中可见，换浏览器或换设备看不到。
- 用户清除浏览器缓存 / 站点数据后，待办会全部丢失，且无法恢复。
- 浏览器无痕 / 隐私模式下，关闭窗口后数据可能被清空。
- 建议在页面底部用一行小字说明：「数据仅保存在本浏览器中，清除浏览器数据后将丢失。」

### 6.2 数据结构

localStorage 键名：`todo-list:items`

值为 JSON 数组，每个元素结构如下：

```json
{
  "id": "string，唯一标识，如 crypto.randomUUID() 或时间戳+随机数",
  "text": "string，trim 后的待办内容，1–200 字符",
  "completed": false,
  "createdAt": 1793500000000
}
```

数组按显示顺序存储（最新在前）。

### 6.3 异常处理

- localStorage 中没有该键：视为空列表，显示空状态。
- 数据无法解析（JSON 损坏或格式不符）：视为空列表并覆盖为合法空数组，页面不报错、不白屏。
- localStorage 不可用或写入失败（如存储已满、浏览器禁用）：页面功能仍可在本次会话内使用，并给出一条不打扰的提示「当前无法保存到本地，刷新后数据将丢失」。

## 7. 非功能需求

- **风格**：现代、简洁、专业，避免过度设计；以浅色背景、清晰层级、充足留白为主，不使用复杂动画和装饰插画。
- **响应式**：桌面端与移动端（宽度 ≥ 320px）均可正常使用，内容区在桌面端居中、限制最大宽度。
- **可访问性**：输入框有可读标签（可视或 aria-label）；勾选框和删除按钮可通过键盘 Tab 聚焦并用 Enter / 空格操作；删除按钮有 aria-label「删除待办」。
- **长文本**：200 字符的长待办应自动换行，不撑破布局、不出现横向滚动。
- **性能**：列表 500 条以内操作无明显卡顿。
- **浏览器支持**：最新版 Chrome、Edge、Safari、Firefox。

## 8. 用户故事与验收标准

### US-01 查看待办列表

**作为**用户，**我想要**打开页面就看到我所有的待办，**以便**了解还有哪些事要做。

- **AC-01-1 加载已有数据**
  - Given localStorage 中已保存 3 条待办
  - When 用户打开页面
  - Then 页面按最新在前的顺序显示这 3 条待办及各自的完成状态
- **AC-01-2 空状态**
  - Given localStorage 中没有待办数据
  - When 用户打开页面
  - Then 页面显示空状态提示，不显示空白列表
- **AC-01-3 数据损坏**
  - Given localStorage 中 `todo-list:items` 的值不是合法 JSON
  - When 用户打开页面
  - Then 页面正常显示空状态，不出现报错或白屏
- **AC-01-4 已完成项展示**
  - Given 列表中有一条已完成的待办
  - When 页面渲染列表
  - Then 该待办的勾选框为选中状态，文字有删除线且视觉上弱化

### US-02 添加新待办

**作为**用户，**我想要**输入一句话就能新增一条待办，**以便**快速记录要做的事。

- **AC-02-1 按钮添加**
  - Given 输入框中输入「回复客户邮件」
  - When 用户点击「添加」按钮
  - Then 列表最上方出现「回复客户邮件」，状态为未完成，输入框被清空并保持焦点
- **AC-02-2 回车添加**
  - Given 输入框中输入「写周报」
  - When 用户按下 Enter
  - Then 列表最上方出现「写周报」，效果与点击按钮一致
- **AC-02-3 空输入**
  - Given 输入框为空
  - When 用户点击「添加」按钮或按 Enter
  - Then 不新增任何待办，列表不变
- **AC-02-4 纯空格**
  - Given 输入框中只有若干空格
  - When 用户点击「添加」按钮或按 Enter
  - Then 不新增任何待办，列表不变
- **AC-02-5 首尾空格去除**
  - Given 输入框中输入「  买牛奶  」
  - When 用户提交
  - Then 列表中新增的待办文本为「买牛奶」
- **AC-02-6 长度限制**
  - Given 用户在输入框中输入或粘贴超过 200 字符的内容
  - When 内容进入输入框
  - Then 输入框中最多只保留 200 个字符，提交后保存的文本不超过 200 字符
- **AC-02-7 新待办置顶**
  - Given 列表中已有待办 A 和 B
  - When 用户添加待办 C
  - Then 列表顺序为 C、A、B
- **AC-02-8 持久化**
  - Given 用户刚添加了一条待办
  - When 用户刷新页面
  - Then 该待办仍在列表中，位置与状态不变

### US-03 标记完成 / 取消完成

**作为**用户，**我想要**勾选已完成的待办，也能取消勾选，**以便**跟踪进度并纠正误操作。

- **AC-03-1 标记完成**
  - Given 列表中有一条未完成的待办
  - When 用户点击其勾选框
  - Then 该待办变为已完成状态，显示删除线样式
- **AC-03-2 取消完成**
  - Given 列表中有一条已完成的待办
  - When 用户再次点击其勾选框
  - Then 该待办恢复为未完成状态，删除线样式消失
- **AC-03-3 位置不变**
  - Given 列表顺序为 A、B、C，均未完成
  - When 用户将 B 标记为已完成
  - Then 列表顺序仍为 A、B、C
- **AC-03-4 持久化**
  - Given 用户将某条待办标记为已完成
  - When 用户刷新页面
  - Then 该待办仍为已完成状态
- **AC-03-5 键盘操作**
  - Given 焦点位于某条待办的勾选框上
  - When 用户按下空格键
  - Then 该待办的完成状态被切换

### US-04 删除待办

**作为**用户，**我想要**一键删除不需要的待办，**以便**保持列表整洁。

- **AC-04-1 直接删除**
  - Given 列表中有待办 A、B、C
  - When 用户点击 B 的删除按钮
  - Then B 立即从列表移除，不弹出确认框，列表变为 A、C
- **AC-04-2 删除最后一条**
  - Given 列表中只剩一条待办
  - When 用户删除这条待办
  - Then 页面显示空状态提示
- **AC-04-3 持久化**
  - Given 用户删除了一条待办
  - When 用户刷新页面
  - Then 被删除的待办不再出现
- **AC-04-4 删除已完成项**
  - Given 列表中有一条已完成的待办
  - When 用户点击其删除按钮
  - Then 该待办被移除，其余待办顺序与状态不变

### US-05 了解数据存储方式

**作为**用户，**我想要**知道我的数据存在哪里，**以便**避免误清除导致数据丢失。

- **AC-05-1 本地存储说明**
  - Given 用户打开页面
  - When 页面渲染完成
  - Then 页面底部显示说明「数据仅保存在本浏览器中，清除浏览器数据后将丢失。」
- **AC-05-2 存储不可用提示**
  - Given 浏览器禁用了 localStorage 或存储写入失败
  - When 用户添加、勾选或删除待办
  - Then 操作在当前页面内正常生效，并显示提示「当前无法保存到本地，刷新后数据将丢失」
