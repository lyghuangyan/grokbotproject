## 1. 背景与目标

用户需要一个打开即用的轻量待办工具，用来快速记下要做的事、勾掉已完成的事、清掉不需要的事。

本期目标是交付一个单页 Web 应用，覆盖待办的「查看、添加、标记完成/未完成、删除」四个核心动作，数据保存在浏览器本地（localStorage），刷新页面后数据不丢失。

**成功标准**

- 四个核心功能全部可用，且满足第 5 节的交互规则。
- 刷新或关闭后重新打开页面，待办列表与完成状态保持一致。
- 页面风格现代、简洁、专业，无多余装饰。
- 第 8 节全部 P0、P1 验收标准通过。

## 2. 范围

### 2.1 本期要做

1. 显示待办列表（含空状态）
2. 添加新待办
3. 标记完成 / 取消完成
4. 删除待办
5. 数据保存在浏览器 localStorage
6. 列表底部统计（规则见 F6）

### 2.2 本期不做

以下内容明确不在本期范围内，开发与设计不应实现或预留可见入口：

- 登录 / 账号体系
- 后端服务与接口
- 同步：多端、多浏览器数据同步，以及**同一浏览器多个标签页之间的实时同步**（不监听 `storage` 事件，以最后一次写入为准，见 6.4）
- 编辑已有待办的内容
- 分类 / 标签
- 截止日期 / 提醒
- 拖拽排序
- 筛选（如「全部 / 未完成 / 已完成」切换）
- 字数计数显示（如「12/200」）
- 从备份恢复数据的界面入口（备份键 `todo-list:items.bak` 仅供人工排查）

## 3. 目标用户与使用场景

- **目标用户**：需要临时记录个人事项的普通用户，单人、单设备使用。
- **典型场景**：工作间隙打开页面，输入「回复客户邮件」并回车添加；完成后勾选；不需要的条目直接删除。

## 4. 功能需求

### F1 显示待办列表

- 页面加载时从 localStorage 读取数据，按 6.3 的规则校验后渲染列表。
- 每条待办展示：完成状态勾选框、待办文本、删除按钮。
- 待办文本一律按纯文本渲染（如 React 文本节点或 `textContent`），不得使用 `innerHTML` / `dangerouslySetInnerHTML`；`<script>`、HTML 标签、实体都按原文显示。
- 已完成的待办以视觉区分（文字删除线 + 降低对比度），但仍保留在列表原位置。
- 列表为空时显示空状态提示「还没有待办，添加一条吧」。
- 列表顺序：**以存储数组的顺序为准**（新待办插入数组头部，因此最新在最上方）；`createdAt` 只作记录，不参与排序。

### F2 添加新待办

- 页面顶部提供一个输入框和一个「添加」按钮。
- 用户可点击「添加」按钮或在输入框中按 Enter 提交。
- 输入规则（详见第 5 节）：
  - 空输入、纯空白（含全角空格、Tab、不换行空格等 `String.prototype.trim` 能去掉的字符）、只含零宽字符（U+200B、U+200C、U+200D、U+2060、U+FEFF）时，视为空输入：不添加、不清空输入框、「添加」按钮禁用、Enter 无效。
  - 保存时先删除零宽字符（U+200B、U+200C、U+200D、U+2060、U+FEFF），再去除首尾空白（`trim()`），中间空格保留。例如输入「\u200B买菜」保存为「买菜」。
  - 粘贴含换行的文本时，每处换行（`\r\n`、`\n`、`\r`）替换为一个空格，再计算长度。
  - 最大长度 200，按 JavaScript 字符串长度（`.length`）计算；输入或粘贴超长时截断至 200。截断点落在 emoji 代理对中间时，整个字符不保留，不得出现孤立代理项或乱码（�）。组合 emoji（如 👨‍👩‍👧‍👦）在上限处被拆开可以接受。
  - 输入法组字过程中（`isComposing` 为 true 或 keyCode 229）按 Enter 只上屏，不提交。
  - 防重复提交：一次提交只新增一条；快速双击按钮、连按或长按 Enter、Enter 与点击同时触发，都只新增一条。
  - 允许添加与已有待办文本相同的内容，各自有独立 id。
- 添加成功后：新待办插入列表最上方，默认未完成；输入框清空并保持焦点，方便连续添加。

### F3 标记完成 / 取消完成

- 点击勾选框或点击待办文本区域（整行 label）切换完成状态。
- 键盘：焦点在勾选框上时按空格切换（原生 checkbox 行为）；Enter 不要求响应。
- 切换后待办位置不变，不自动移到底部或顶部。
- 状态变化立即写入 localStorage。

### F4 删除待办

- 每条待办提供删除图标按钮：≥1024px 且设备支持悬停时，行悬停或按钮聚焦时显示；其余情况（<1024px，或 `(hover: none)` 的触屏设备）常显。
- 点击、或焦点在按钮上按 Enter / 空格，直接删除，不弹出确认框。
- 删除后焦点（鼠标删除与键盘删除使用同一规则）：移到下一条的删除按钮；没有下一条时移到上一条的删除按钮；列表删空时移到输入框。焦点不得落到 `body`。
- ≥1024px 鼠标设备上，用鼠标删除后下一条的删除按钮因获得焦点而显示出来，属于可接受的表现；焦点环是否显示按浏览器 `:focus-visible` 默认行为，不作要求。
- 删除后立即写入 localStorage；若删除后列表为空，显示空状态。

### F5 本地数据存储

- 使用浏览器 localStorage 保存全部待办数据，键名 `todo-list:items`。
- 任何新增、状态切换、删除后立即写入**完整的内存列表**（不做增量写入）。
- 进入「仅内存模式」（见 F7）后，本次会话不再写入存储；存储恢复可用也不自动补写，下次打开页面时重新尝试。
- 页面刷新、关闭后重新打开，数据保持一致。
- 存储不可用、写入失败或备份失败时的处理见 6.3 和 F7。

### F6 底部统计

N 为未完成待办数，M 为待办总数。统计文案规则如下（与开发实现及设计稿 v1.7 对齐）：

| 状态 | 桌面端 / 平板（>480px） | 窄屏（≤480px） |
| --- | --- | --- |
| M = 0（空列表） | 隐藏统计 | 隐藏统计 |
| N > 0 | 「剩余 N 项 · 共 M 项」（两项必须显示） | 「剩余 N 项」 |
| N = 0 且 M > 0（全部完成） | 只显示「全部完成」，不显示「共 M 项」 | 只显示「全部完成」 |

- 添加、勾选/取消勾选、删除后，统计实时更新，无需刷新。
- 统计容器带 `aria-live="polite"`，并且**始终保留在 DOM 中**；M = 0 时清空内容并在视觉上隐藏，不销毁节点，保证后续变化仍能被读屏播报。

### F7 存储异常与「仅内存模式」

- **触发条件**（三种情况统一处理）：
  1. 页面加载时存储不可用：读取抛异常，或探测写入失败（包括「可读但不可写」，如配额已满）；
  2. 本次会话中任意一次写入失败（如 QuotaExceededError）；
  3. 加载修复数据时备份到 `todo-list:items.bak` 失败。
- **进入仅内存模式后**：
  - 本次会话停止对 localStorage 的一切写入（包括 `todo-list:items` 和 `.bak`），之后的增、改、删只保存在内存中，页面上正常生效；
  - 即使存储在本次会话中恢复可用，也不再写入、不补写；
  - 提示条在本次会话全程常驻，不自动消失，只显示一条；
  - 下次打开或刷新页面时重新检测存储，可用则恢复正常读写，提示条不再显示。
- **加载时的数据显示**：
  - 存储无法读取：显示空状态。
  - 存储可读但不可写：照常读取并按 6.3 校验，显示合法元素；需要修复时不备份、不回写，原值保持不变。
  - 备份失败：不覆盖原值，只显示合法元素；没有合法元素时显示空状态。
- **加载检测**：写入探测键 `todo-list:probe` 后立即删除，探测键不残留。存储中只会出现 `todo-list:items` 和 `todo-list:items.bak`（后者仅在修复过数据后存在）。
- **提示条**：在输入区下方显示，文案固定为「当前无法保存到本地，本次的修改不会被保存，关闭或刷新页面后将丢失。」，`role="status"`；不弹窗、不阻断操作。
- 数据损坏被自动修复且备份成功时**不**显示提示条。
- 样式和位置以设计稿 v1.7 第 4.7 节为准。

## 6. 数据说明

### 6.1 数据只保存在本地

本期数据仅保存在当前浏览器的 localStorage 中，没有任何后端或云端存储。这意味着：

- 数据只在当前设备、当前浏览器中可见，换浏览器或换设备看不到。
- 用户清除浏览器缓存 / 站点数据后，待办会全部丢失，且无法恢复。
- 浏览器无痕 / 隐私模式下，关闭窗口后数据可能被清空。
- 页面底部用一行小字说明：「数据仅保存在本浏览器中，清除浏览器数据后将丢失。」

### 6.2 数据结构

| 键名 | 用途 |
| --- | --- |
| `todo-list:items` | 待办数据（唯一的业务键） |
| `todo-list:items.bak` | 仅在加载时发现数据需要修复时写入，保存修复前的原始字符串；只保留最近一次，覆盖写入 |
| `todo-list:probe` | 加载时探测存储是否可写，写入后立即删除，不残留 |

`todo-list:items` 的值为 JSON 数组，每个元素结构如下：

```json
{
  "id": "string，唯一标识，如 crypto.randomUUID() 或时间戳+随机数",
  "text": "string，trim 后的待办内容，1–200 字符（JS 长度）",
  "completed": false,
  "createdAt": 1793500000000
}
```

数组按显示顺序存储（最新在前），显示时以数组顺序为准。

### 6.3 加载校验与异常处理

**处理顺序**：读取 → 解析 JSON → 逐条校验（含 trim）→ 在合法元素中按 id 去重（保留第一条）→ 如有元素被丢弃，先备份再回写。

| 情况 | 处理 | 是否备份 | 是否提示 |
| --- | --- | --- | --- |
| 键不存在、值为 `[]` 或空字符串 `""` | 视为空列表，显示空状态 | 否 | 否 |
| 值不是合法 JSON（如 `{abc`） | 原始字符串写入 `todo-list:items.bak`，再把 `todo-list:items` 重置为 `[]`，显示空状态 | 是 | 否 |
| 合法 JSON 但不是数组（`{}`、`"str"`、`123`、`null`、`true`） | 同上 | 是 | 否 |
| 数组中部分元素不合法 | 只丢弃不合法元素，合法元素保持原顺序显示；原始字符串写入 `.bak`，清理后的数组写回 `todo-list:items` | 是 | 否 |
| 合法元素中 id 重复 | 保留第一条，丢弃后续同 id 元素；按上一行处理 | 是 | 否 |
| 元素只多出字段，或 text 带首尾空白，其余合法 | 视为合法，内存中忽略多余字段、使用 trim 后的 text；**不备份、不立即回写**，下次正常写入时自然按标准结构保存 | 否 | 否 |
| 备份写入失败 | 不覆盖原值，进入仅内存模式（F7）；只显示合法元素，没有合法元素时显示空状态 | — | 是 |
| 存储可读但不可写 | 照常显示合法元素，不备份、不回写，进入仅内存模式 | — | 是 |
| 存储无法读取 | 显示空状态，进入仅内存模式 | — | 是 |
| 会话中写入失败 | 本次操作在页面上照常生效，进入仅内存模式 | — | 是 |

- **合法元素判定**（先 trim 再判定）：是对象；`id` 为非空字符串；`text` 为字符串，`trim()` 后长度 ≤ 200，且删除零宽字符再 `trim()` 后非空；`completed` 为布尔值；`createdAt` 为有限数字。任一项不满足即为不合法，**不做类型修正、不截断**。多余字段不影响合法性。
- **零宽字符只参与合法性判断**：删除零宽字符再 `trim()` 只用来决定元素是否合法。显示文本和写回 `todo-list:items` 的 `text` 只做 `trim()`，不删除零宽字符。因此已保存的 `a\u200Bb` 在加载后原样保留。用户新保存的输入仍然先删除零宽字符再 `trim()`。
- **去重在校验之后**：同 id 的第一条若不合法已被丢弃，后面合法的同 id 元素保留。
- 任何情况下页面不报错、不白屏，控制台无未捕获异常。

### 6.4 多标签页（已知限制）

本期不做多标签页同步。同一浏览器打开多个标签页时，各标签页只在加载时读取一次数据，之后以最后一次写入为准：另一标签页的新增可能被覆盖，已删除的条目可能在另一标签页操作后「复活」。刷新页面可看到最新的已保存数据。要求不报错、不产生重复 id。

## 7. 非功能需求

- **风格**：现代、简洁、专业，避免过度设计；以浅色背景、清晰层级、充足留白为主，不使用复杂动画和装饰插画。
- **响应式**：断点 ≥1024px 桌面、481–1023px 平板、≤480px 移动，最小支持 320px；任何宽度不出现横向滚动；具体布局和字号以设计稿 v1.7 第 3、5 节为准。
- **可访问性**：输入框有可读标签（可视或 `aria-label="新待办"`）；Tab 顺序为输入框 → 添加按钮 → 每条的勾选框 → 删除按钮，焦点可见；勾选框用空格切换；删除按钮用 Enter / 空格触发，`aria-label="删除待办"`；移动端「+」按钮 `aria-label="添加"`；列表用 `<ul>/<li>`；统计区 `aria-live="polite"`；对比度满足 WCAG AA。
- **长文本**：200 字符的长待办（含无空格的连续字符和长 URL）自动换行，不撑破布局。
- **性能**（测量环境：桌面 Chrome 最新版、不降速，500 条数据夹具 FX-500）：首屏 ≤ 1 秒；添加、切换、删除单次操作 ≤ 100 毫秒；长任务 ≤ 200 毫秒作为参考指标记录，不作为验收门槛。
  - **计时终点统一为 DOM 更新后的下一帧**：在 DOM 更新提交后的下一个 `requestAnimationFrame` 回调中打点。
  - **开发打点**（`performance.mark`）：首屏在列表首次渲染完成后的下一帧打 `list-rendered`，首屏耗时 = 该 mark 的 `startTime`（起点为导航开始）；单次操作在事件处理开始时打 `op-start`，DOM 更新后的下一帧打 `op-end`，用 `performance.measure('op', 'op-start', 'op-end')` 得到耗时。
- **安全**：待办文本一律纯文本渲染，存储中的恶意内容同样不执行。
- **质量**：全流程（增、改、删、刷新、空状态、数据损坏、存储禁用）控制台无 error 和未捕获异常。
- **浏览器支持**：最新版 Chrome、Edge、Safari、Firefox，以及 iOS Safari、Android Chrome。

## 8. 用户故事与验收标准

### US-01 查看待办列表

**作为**用户，**我想要**打开页面就看到我所有的待办，**以便**了解还有哪些事要做。

- **AC-01-1 加载已有数据**
  - Given localStorage 中已保存 3 条合法待办
  - When 用户打开页面
  - Then 页面按存储数组顺序（最新在前）显示这 3 条待办及各自的完成状态
- **AC-01-2 空状态**
  - Given `todo-list:items` 不存在、值为 `[]` 或为空字符串
  - When 用户打开页面
  - Then 页面显示空状态提示「还没有待办，添加一条吧」，不显示空白列表和底部统计
- **AC-01-3 数据不是合法 JSON**
  - Given `todo-list:items` 的值为 `{abc`
  - When 用户打开页面
  - Then `todo-list:items.bak` 的值为 `{abc`，`todo-list:items` 被重置为 `[]`，页面显示空状态，不显示存储提示条，不报错、不白屏
- **AC-01-4 已完成项展示**
  - Given 列表中有一条已完成的待办
  - When 页面渲染列表
  - Then 该待办的勾选框为选中状态，文字有删除线且视觉上弱化，位置不变
- **AC-01-5 数据不是数组**
  - Given `todo-list:items` 的值依次为 `{}`、`"str"`、`123`、`null`、`true`
  - When 每次写入后刷新页面
  - Then 每次都把原值备份到 `todo-list:items.bak`、把 `todo-list:items` 重置为 `[]`，显示空状态，不报错
- **AC-01-6 部分元素不合法**
  - Given 存储数组为 [合法 A, `null`, 合法 B, `{"id":"x","text":"","completed":false,"createdAt":1}`]
  - When 用户打开页面
  - Then 页面只显示 A、B（顺序不变）；`todo-list:items.bak` 为原始字符串；`todo-list:items` 被写回为只含 A、B 的数组
- **AC-01-7 id 重复**
  - Given 存储中有两条 id 相同、文本不同的元素，第一条为 X，第二条为 Y
  - When 用户打开页面
  - Then 只显示 X；原始字符串已备份；之后切换或删除 X 只影响 X
- **AC-01-8 存储内容按纯文本显示**
  - Given 存储中某条待办的 text 为 `<img src=x onerror=alert(1)>`
  - When 用户打开页面并切换、删除这条待办
  - Then 该文本原样显示，没有弹窗，没有图片请求，DOM 中没有新增元素
- **AC-01-9 显示顺序以数组为准**
  - Given 存储数组第 1 条的 createdAt 早于第 2 条
  - When 用户打开页面
  - Then 列表仍按数组顺序显示，第 1 条在上
- **AC-01-10 零宽文本元素不合法**（v1.3）
  - Given 存储数组为 [合法 A, text 为 `\u200B` 的元素]
  - When 用户打开页面
  - Then 只显示 A；原始字符串已备份到 `.bak`，`todo-list:items` 写回为只含 A 的数组
- **AC-01-11 多余字段与首尾空白不触发修复**（v1.3）
  - Given 存储中只有一条元素 `{"id":"a","text":" a ","completed":false,"createdAt":1,"extra":1}`
  - When 用户打开页面
  - Then 页面显示「a」；不写入 `.bak`，`todo-list:items` 原值不变；用户下一次正常操作后，存储中该条为 `{id, text:"a", completed, createdAt}`，不含 `extra`
- **AC-01-12 先校验再去重**（v1.3）
  - Given 存储数组为 [`{"id":"x","text":"","completed":false,"createdAt":1}`, `{"id":"x","text":"Y","completed":false,"createdAt":2}`]
  - When 用户打开页面
  - Then 第一条因不合法被丢弃，显示 Y；原始字符串已备份

  - When 用户刷新页面
  - Then 该待办仍在列表中，位置与状态不变
- **AC-02-9 零宽字符视为空**
  - Given 输入框中只有 `\u200B\u200B`
  - When 用户尝试提交
  - Then 按钮为禁用态，不新增待办
- **AC-02-10 粘贴换行**
  - Given 用户复制了「第一行\n第二行」
  - When 粘贴到输入框并提交
  - Then 保存和显示的文本为「第一行 第二行」，不含换行符

  - Given 输入框已有 199 个「a」
  - When 用户输入或粘贴 1 个 😀
  - Then 😀 不被插入，长度保持 199；任何情况下输入框和存储中都不出现孤立代理项或 �
- **AC-02-12 输入法组字时按 Enter**
  - Given 用户用拼音输入法输入「xiezhoubao」，候选框处于组字状态

  - Then 第一次 Enter 只上屏文字，不新增待办；第二次 Enter 新增一条「写周报」，不出现拼音残留或重复两条

  - Then 只新增一条「A」，id 唯一
- **AC-02-14 输入内容按纯文本显示**

  - Then 每条都原样显示为文本，不加粗、不解码实体、不弹窗，DOM 中没有新增 script/svg 节点

  - Then 列表中出现两条「写周报」，id 不同，可分别勾选和删除

### US-04 删除待办

  - Given 用户删除了一条待办
  - When 用户刷新页面
  - Then 被删除的待办不再出现
- **AC-04-4 删除已完成项**
  - Given 列表中有一条已完成的待办
  - When 用户点击其删除按钮
  - Then 该待办被移除，其余待办顺序与状态不变
- **AC-04-5 键盘删除**

  - Then 该条被删除

  - When 用户删除 B，再删除 C，再删除 A
  - Then 删 B 后焦点在 C 的删除按钮；删 C 后焦点在 A 的删除按钮；删 A 后焦点在输入框；焦点始终不落到 `body`

  - When 用户用鼠标点击 B 的删除按钮
  - Then 焦点移到 C 的删除按钮，规则与 AC-04-6 相同；C 的删除按钮因获得焦点而显示属于可接受表现；焦点环是否显示不作要求

### US-05 了解数据存储方式

- **AC-05-1 本地存储说明**

- **AC-05-3 会话中写入失败后停止写入**
  - Given 页面加载时存储可用，之后存储配额已满
  - When 用户添加一条待办（写入失败），随后再勾选、删除
  - Then 所有操作在页面上正常生效，统计正确；第一次写入失败时显示同一提示条；之后的操作不再尝试写入存储；不弹窗、不阻断操作
- **AC-05-4 恢复后不补写，下次打开重试**（v1.3 修改）
  - Given 已进入仅内存模式，提示条正在显示，内存中有未保存的修改
  - When 本次会话中存储恢复可用后用户继续操作，然后刷新页面
  - Then 刷新前提示条一直常驻且只有一条，存储内容不变；刷新后页面重新检测存储，可用则不再显示提示条，列表为最后一次成功保存的数据，本次会话的修改不存在
- **AC-05-5 存储可读但不可写**（v1.3）
  - Given 存储中已有 3 条合法待办，且同源存储配额已满（读取正常、写入失败）
  - When 用户打开页面并添加一条待办
  - Then 页面正常显示已有 3 条和新添加的 1 条，显示提示条；`todo-list:items` 的值保持原来的 3 条
- **AC-05-6 备份失败（有合法元素）**（v1.3）
  - Given 存储数组为 [合法 A, `null`]，且写入 `.bak` 会失败
  - When 用户打开页面并进行增、改、删
  - Then 页面显示 A 和后续修改，显示提示条；`todo-list:items` 保持原始值，不写入 `.bak`，本次会话不再写入存储
- **AC-05-7 备份失败（无合法元素）**（v1.3）
  - Given `todo-list:items` 的值为 `{abc`，且写入 `.bak` 会失败
  - When 用户打开页面
  - Then 页面显示空状态和提示条；`todo-list:items` 仍为 `{abc`

  - When 查看 Application → Local Storage
  - Then 前者只有 `todo-list:items`；后者只有 `todo-list:items` 和 `todo-list:items.bak`；任何时候都没有 `todo-list:probe`

### US-06 查看待办统计

**作为**用户，**我想要**在列表底部看到还剩多少项没做、一共有多少项，**以便**快速掌握整体进度。

- **AC-06-8 窄屏统计**
  - Given 窗口宽度 ≤480px，列表中有 3 条待办，其中 1 条已完成
  - When 页面渲染列表
  - Then 底部只显示「剩余 2 项」，不显示「共 3 项」；宽度拖到 481px 时立即变为「剩余 2 项 · 共 3 项」

### US-07 用键盘和读屏软件使用（v1.2 新增）

**作为**只用键盘或依赖读屏软件的用户，**我想要**不用鼠标也能完成全部操作并听到变化，**以便**正常使用这个工具。

- **AC-07-1 Tab 顺序与焦点可见**
  - Given 列表中有 3 条待办
  - When 用户从页面顶部连续按 Tab
  - Then 焦点依次经过输入框 → 添加按钮 → 每条的勾选框 → 删除按钮，每个控件都有清晰的焦点环；桌面端删除按钮获得焦点时可见
- **AC-07-2 可访问名称与语义**
  - Given 页面已加载（桌面与 ≤480px 各一次）
  - When 用 Accessibility 面板或 axe 检查
  - Then 输入框有可读标签；删除按钮名称为「删除待办」；移动端「+」按钮名称为「添加」；列表为 `<ul>/<li>`；axe 无严重（critical / serious）问题
- **AC-07-3 统计播报**
  - Given 用户开启 VoiceOver 或 NVDA，列表非空
  - When 用户勾选、添加、删除待办，最后删光
  - Then 前三步后读屏在当前播报结束后读出新的统计；统计容器带 `aria-live="polite"` 且不被销毁重建；删光后不读出残留数字（空状态是否播报不作要求）
- **AC-07-4 纯键盘完成全流程**
  - Given 用户不使用鼠标
  - When 用户输入文字按 Enter 添加、Tab 到勾选框按空格完成、Tab 到删除按钮按 Enter 删除
  - Then 三个操作都成功，焦点始终可见且不丢失

### US-08 在不同设备和数据量下稳定使用（v1.2 新增）

**作为**用户，**我想要**在手机、平板、电脑上和待办很多时都能顺畅使用，**以便**随时随地记录。

- **AC-08-1 最小宽度无横向滚动**
  - Given 窗口宽度为 320px 和 375px，列表含 1 条 200 个连续「a」的待办和 1 条长 URL
  - When 用户进行增、改、删
  - Then 页面无横向滚动和错位，长文本自动换行，勾选框和删除按钮与首行对齐
- **AC-08-2 断点布局**
  - Given 窗口宽度依次为 1280、1024、1023、768、481、480、320px
  - When 用户观察布局并在各断点间拖动窗口
  - Then ≥1024px 为桌面布局，481–1023px 为平板布局，≤480px 为移动布局（细节以设计稿 v1.7 第 5 节为准）；拖动时布局实时切换，数据、统计、焦点和输入内容不丢失
- **AC-08-3 删除按钮可见性**
  - Given 列表非空
  - When 分别在 ≥1024px 鼠标设备、<1024px、触屏设备上观察
  - Then ≥1024px 鼠标设备上删除按钮在悬停或聚焦时显示；<1024px 或触屏设备上常显
- **AC-08-4 首屏性能**
  - Given 用 FX-500 写入 500 条待办，桌面 Chrome 最新版、不降速
  - When 刷新页面并用 Performance 面板记录
  - Then `list-rendered` mark（DOM 更新后的下一帧）的 `startTime` ≤ 1000 毫秒，不白屏，统计正确
- **AC-08-5 操作性能**
  - Given 已加载 500 条待办
  - When 用户添加 1 条，切换第 1、250、500 条，删除第 1、250、500 条
  - Then 每次操作的 `op` measure（`op-start` → DOM 更新后下一帧的 `op-end`）≤ 100 毫秒，统计正确，刷新后数据一致
- **AC-08-6 控制台无报错**
  - Given 打开 DevTools Console 并保留日志
  - When 依次执行增、改、删、刷新、空状态、数据损坏、存储禁用
  - Then 没有 error 和未捕获异常
- **AC-08-7 本期不做的功能无入口**
  - Given 页面已加载数据
  - When 用户双击待办文本、尝试拖拽待办、查找筛选/标签/日期/登录入口
  - Then 双击不进入编辑，不能拖拽排序，页面上没有上述入口
- **AC-08-8 多标签页不报错**
  - Given 同一浏览器两个标签页 A、B 都显示待办 X
  - When A 删除 X，B 不刷新并切换 X，再刷新两边
  - Then 两边都不报错、不产生重复 id；最终数据以最后一次写入为准（X 可能重新出现，属已知限制，见 6.4）
